\section{Evaluation}
\label{sec:evaluation}

We evaluate CCV along four research questions:

\begin{itemize}
    \item \textbf{RQ1}: How often do LLM agents hallucinate about code?
    \item \textbf{RQ2}: Does deterministic verification catch hallucinations that LLM-as-judge misses?
    \item \textbf{RQ3}: Does claim-calibrated confidence improve downstream decision quality?
    \item \textbf{RQ4}: Which claim types are most commonly hallucinated?
\end{itemize}

\subsection{Dataset}

We evaluate on the CyberGym benchmark~(ICLR 2026): 21 real-world C/C++ vulnerability repositories spanning projects including binutils, curl, libxml2, openssl, php, wireshark, and yara. Each repository contains the vulnerable source code and a vulnerability description from the CyberGym HuggingFace dataset. We generate LLM reasoning about each vulnerability using 7 models, then run CCV to extract and verify claims against the actual source code.

\textbf{Ground truth.} Diff-derived GT from patch files: files and functions modified in the security fix produce expected-\textsc{Verified} claims. Synthetic negatives (typo'd paths, non-existent function names) produce expected-\textsc{Refuted} claims.

\subsection{Baselines}

\begin{itemize}
    \item \textbf{No verification}: Agent confidence as-is (current practice).
    \item \textbf{CCV}: Typed extraction + deterministic verification (our system).
    \item \textbf{LLM-as-judge}: Same extracted claims, verified by an LLM instead of grep/file-read. The judge receives equivalent context to CCV (file contents, grep output) for each claim type.
\end{itemize}

\subsection{Results}

All 7 models exhibit hallucination rates above 30\%, with the worst (GPT-OSS 20B) reaching 50\%. The best performer is Claude Haiku 4.5 at 30.6\%, followed closely by three open models (Granite, Llama, Qwen) clustered at 34--35\%.

Notably, model size does not straightforwardly predict accuracy: the 8B Granite model (34.2\%) outperforms the much larger Claude Sonnet 4 (43.1\%). Sonnet's higher hallucination rate is driven by more aggressive \textsc{Absence} claims that CCV refutes. These findings suggest that hallucination rate depends on claim type distribution, not just model capability.

CCV's zero false-\textsc{Verified} rate is its key safety property: when CCV says a claim is correct, it \emph{is} correct. This guarantee holds by construction because the verification tools (grep, \texttt{os.path.isfile}, lockfile parsing) are deterministic. The LLM-as-judge, by contrast, confirms hallucinated claims 97\% of the time when it disagrees with CCV.

45.8\% of analyses received \textsc{Override}, meaning more than half of the LLM's factual claims were wrong. Only 16.2\% passed CCV's threshold for \textsc{Boost}. Without CCV, all 142 analyses would have been trusted at face value. With CCV, 65 unreliable analyses are flagged before they influence decisions.

\subsubsection{RQ4: Per-Type Analysis}

The hallucination rate varies significantly by claim type. \textsc{File\_Exists} claims (verified via \texttt{os.path.isfile}) are nearly always correct. \textsc{Absence} claims (``no sanitization exists,'' ``no callers found'') are the most commonly hallucinated. This is consistent with the known difficulty of proving negatives through LLM reasoning: an LLM asserting that something does \emph{not} exist is frequently wrong because it lacks complete codebase coverage.

The aggregate ECE across controlled fixtures is 0.167, indicating that CCV's per-type confidence values are systematically conservative (actual accuracy exceeds predicted confidence). This is a desirable property for a safety-critical tool: CCV underpromises.
